# Why no front end

The database holds the records. A coding agent runs the same local commands the operator can inspect. npm run view creates a read-only HTML report, and npm run docs creates draft paperwork. Neither is a reservation interface.

A screen is better for mobile capture, offline work, drag-and-drop itinerary changes, customer self-service and live supplier searching. Those features need separate design and implementation. The free base has no live inventory feed, accounting ledger, payment gateway or automated supplier communication. Enterprise DNA can build agreed screens and connections around the same records.

Local PGlite runs one process at a time. A shared PostgreSQL deployment needs staff authentication, permissions, backups and monitoring. The templates' database owner connection is for controlled operator use, not an anonymous website. Your agent's subscription and hosting remain your costs.
